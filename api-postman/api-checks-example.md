# Пример API-проверок в Postman

## Объект проверки

API-запросы для работы с пользователями на учебном сервисе или тестовом API.

## Цель проверки

Проверить, что сервер корректно обрабатывает HTTP-запросы, возвращает ожидаемые статус-коды и данные в ответе.

---

## Пример 1. Получение списка пользователей

**Метод:** `GET`  
**URL:** `/users`

**Что проверяется:**

| Проверка | Ожидаемый результат |
|---|---|
| Статус-код ответа | `200 OK` |
| Формат ответа | JSON |
| Тело ответа | Содержит список пользователей |
| Время ответа | Запрос выполняется за приемлемое время |

---

## Пример 2. Создание пользователя

**Метод:** `POST`  
**URL:** `/users`

**Тело запроса:**

```json
{
  "name": "Alina",
  "job": "QA Tester"
}
```

**Что проверяется:**

| Проверка | Ожидаемый результат |
|---|---|
| Статус-код ответа | `201 Created` |
| Формат ответа | JSON |
| Имя пользователя | В ответе отображается переданное значение `Alina` |
| Должность пользователя | В ответе отображается переданное значение `QA Tester` |

---

## Пример 3. Ошибка при запросе несуществующего пользователя

**Метод:** `GET`  
**URL:** `/users/999999`

**Что проверяется:**

| Проверка | Ожидаемый результат |
|---|---|
| Статус-код ответа | `404 Not Found` |
| Тело ответа | Сервер сообщает, что пользователь не найден или возвращает пустой ответ |
| Поведение сервера | Сервер не возвращает ошибку `500 Internal Server Error` |

---

## Примечание

Такие проверки помогают убедиться, что API корректно обрабатывает успешные и ошибочные сценарии, а ответы сервера соответствуют ожидаемому формату.
